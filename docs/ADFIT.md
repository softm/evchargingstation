# AdFit 배너 연결

2026-10-20 배너 코드와 배치를 구현했고, 2026-10-24 충전한눈 전용 Web 매체와 광고단위 3개를 발급해 운영 설정에 연결했다. 매체 심사와 실제 광고 노출·수익은 AdFit 관리 화면에서 별도로 확인한다.

## 배치와 동작

- 목록 6개 뒤에 300 × 250 배너 1개를 표시한다. 목록의 일반 스크롤 안에 있어 검색·결과 헤더 높이와 지도 면적을 줄이지 않는다.
- 하단 접이식 지면은 PC 728 × 90, 모바일 320 × 100 전용 단위를 사용한다. 첫 로드에서 기본 펼침으로 현재 규격의 광고를 한 번 요청하고, 사용자가 접은 선택은 같은 탭에서 유지한다.
- 결과가 6개 이하이면 숨긴다. 슬롯이 화면에 절반 이상 보일 때 페이지당 최초 1회 공식 SDK를 요청한다. 모바일 지도 탭처럼 목록이 숨겨져 있으면 요청하지 않는다.
- 목록을 앞 6개/배너/나머지로 나누어 필터·지도 이동·상태 갱신 때 배너 iframe을 삭제하거나 다시 만들지 않는다. 배너 때문에 검색 결과 수·마커 번호는 바꾸지 않는다.
- NO-AD 콜백, 스크립트 실패, 8초 동안 iframe이 생기지 않은 경우 슬롯을 접고 같은 페이지에서 재시도하지 않는다. iframe 생성 여부는 유료 노출 증거로 사용하지 않는다.
- 설정 없음·비활성·화면 체험·운영 Origin/경로 외에서는 실광고를 요청하지 않는다. 좁은 목록에서 320px 광고를 축소·잘라 표시하지 않는다.
- `?ad-preview=1`은 실광고를 전혀 호출하지 않는 배치 확인용 상자다. 실제 광고와 명시적으로 구분한다.

## 실제 광고 연결에 필요한 설정

1. [AdFit](https://adfit.kakao.com/)의 충전한눈 전용 Web 매체에 목록 300 × 250, 하단 PC 728 × 90, 하단 모바일 320 × 100 단위를 각각 발급한다.
2. 발급된 `DAN-…`를 `public/ad-config.js` 또는 대응하는 Actions Variable에 넣는다. 광고단위 ID는 공개 설정으로 Secret이 아니며, 발급 규격과 코드 규격을 반드시 일치시킨다.
3. 워크플로를 배포한 뒤 실제 브라우저에서 최초 요청과 NO-AD 여부를 확인한다. 광고 클릭으로 시험하거나 반복 새로고침으로 노출을 만들지 않는다. 매체 승인·실제 노출·수익은 계정에서 별도 확인한다.

운영 연결 값은 [광고 운영 문서](ADS.md)를 기준으로 관리한다. 다른 매체의 광고단위를 충전한눈용으로 표시하거나 재사용하지 않는다.

## 참고한 소스와 공식 계약

사용자 소유 [돌봄한눈](https://github.com/softm/homecare-nationwide-care-services-map)의 `nationwide-care-ad-config.js`, `care-list-ad-config.js`, 배너 초기화와 NO-AD 처리 방식을 참고하여 별도 모듈로 작성했다. 원본 저장소와 광고단위는 변경하지 않았다.

- [공식 Web SDK 가이드](https://github.com/adfit/adfit-web-sdk): `ins.kakao_ad_area`, 발급받은 크기·단위 정보, 비동기 `ba.min.js`, `data-ad-onfail` 콜백.
- [공식 운영정책](https://adfit.kakao.com/web/html/use_kakao.html): 등록 매체, 광고와 조작부 구분, 콘텐츠 가림 방지, 반복 호출 방지.

실제 요청에는 공식 스크립트를 그대로 사용한다. 테스트는 가짜 DOM/SDK로 수행하며 실제 광고 네트워크를 호출하지 않는다.
