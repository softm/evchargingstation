# 전기차 충전소 API 수집과 데이터 정확성

이 문서는 충전한눈의 공공데이터 수집기와 HTTP API가 어떤 근거로 동작하는지 설명한다. 실제 서비스키가 제공되지 않은 개발 환경에서 구현했으며, 실시간 API 호출 성공이나 전국 데이터 수집 완료를 주장하지 않는다. 키가 없으면 실제 충전소를 임의로 생성하지 않는다.

## 확인한 공식 자료

| 자료 | 확인 내용 |
| --- | --- |
| [한국환경공단 전기자동차 충전소 정보](https://www.data.go.kr/data/15076352/openapi.do) | 2026-10-19 확인. 포털 수정일 2026-07-21, 참고문서 v1.25, 공식 HTTPS API 주소, 개발계정 표시 트래픽 1,000, 출처표시 조건 |
| 사용자가 첨부한 OpenAPI 활용가이드 v1.25 | 전체 문서의 요청·응답·공통코드 확인. 최신 개정 이력은 2026-07-01 |
| [무공해차 통합누리집](https://ev.or.kr/) | 이용자가 공식 정보를 확인할 수 있는 안내 링크. 본 서비스에서 충전요금이나 대기시간을 가져오는 데이터 소스로 연결한 것은 아님 |

문서의 예제에는 HTTP가 남아 있지만 실제 구현은 포털의 HTTPS 주소를 사용한다. 포털의 간략 요청표와 가이드의 상세 명세에는 일부 누락·표기 차이가 있다. 이후 실제 서비스키를 연결하면 가이드 기반 계약을 실제 응답과 함께 검증해야 한다.

## 기존 돌봄 지도 수집 구조를 참고한 범위

지도 관련 실제 소스 재사용 내역과 원본 버전은 [SOURCE_REUSE.md](SOURCE_REUSE.md)를 함께 확인한다. API 수집기는 다음 기존 파일의 구조를 읽고 공통 설계 원칙을 적용한 새 구현이다. NHIS·심평원의 엔드포인트, 기관 데이터, 인증 설정을 전기차 데이터와 섞지 않는다.

| 원본 파일과 함수 | 확인한 동작 | 이번 구현에 적용한 부분 |
| --- | --- | --- |
| `homecare-nationwide-care-services-map/scripts/sync_nhis_static.py`의 `write_json`, `write_gzip_json` | 임시 파일 작성 후 교체하는 원자적 저장 | `server/client.py`의 `atomic_json`을 새로 구현. 같은 디렉터리의 임시 파일, fsync, os.replace 사용 |
| 같은 파일의 `DataGoClient.request_xml` | 호출 예산, API 결과코드 확인, 오류별 재시도 | `OpenDataClient`와 `CallBudget`을 새로 구현. 재시도 각각을 예산에 포함하고 원본 오류문·인증키 URL을 로그에서 제외 |
| 같은 파일의 `fetch_all_pages` | 모든 API 페이지를 읽어 목록 구성 | EvCharger의 최대 9,999건과 상태조회 특성에 맞춘 전체 페이지 순회 및 검증 |
| 같은 파일의 `save_checkpoint` | 수집 진행·완료·호출량의 별도 기록 | `.cache/evchargingstation/state.json`, `budget.json`에 비공개 실행 상태 저장 |
| `homecare-nationwide-care-services-map/scripts/build_nationwide_care_services.py`의 `main`, `write_json` | 목록 파일을 먼저 작성하고 manifest에 경로·개수·출처를 연결 | 실제 응답 지역코드로 분할한 불변 JSON 파일을 만든 뒤 manifest를 마지막에 교체 |

수집기 Python 코드에 원본 파일을 직접 복사한 것은 아니다. 원본을 읽고 저장·예산·페이지·manifest 구조를 참고했으며, 전기차 API에 필요한 상태 변경분 병합과 최신성 판단을 별도로 구현했다.

## 실행 방법

Python 3.11 이상이면 별도 Python 패키지 설치 없이 실행할 수 있다. 인증키는 `DATA_GO_KR_SERVICE_KEY` 환경변수만 사용한다. 공개 JavaScript 설정, 정적 데이터, CLI 인자에 서비스키를 넣지 않는다.

```bash
# 최초 전국 수집
python3 scripts/collect.py --mode full

# 기본 운영: 저장된 상태와 경과시간에 따라 변경분 또는 전체 복구
python3 scripts/collect.py --mode auto

# 변경분 요청. 기반 목록이 없거나 조회 가능 기간을 넘기면 전체 복구
python3 scripts/collect.py --mode status --period 10

# 지도 정적 파일과 공유 API를 같은 서버에서 제공
python3 -m server --host 127.0.0.1 --port 8000

# 저장된 데이터만 확인하고 백그라운드 수집은 시작하지 않기
python3 -m server --no-poll
```

키의 실제 값은 저장소의 문서나 예제에 작성하지 않는다. 실행 환경의 비밀정보 설정에서 주입한다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 없음 | 공공데이터 서비스키. 인코딩키·디코딩키를 한 번만 인코딩하여 요청 |
| `MAX_API_CALLS_PER_RUN` | 100 | 한 수집 실행의 요청 시도 수 상한 |
| `MAX_API_CALLS_PER_DAY` | 1,000 | 이 캐시를 사용하는 수집기의 KST 일일 호출 예산 |
| `STATUS_POLL_INTERVAL_SECONDS` | 300 | 서버의 수집 실행 종료 후 다음 실행까지 대기시간. 60~600 허용 |
| `INVENTORY_REFRESH_SECONDS` | 86,400 | 자동 모드의 전체 목록 재수집 간격 |
| `RELEASE_RETENTION` | 3 | 최근 분할 데이터 배포본 보존 수. 최소 2개 |
| `EV_ALLOWED_ORIGINS` | 없음 | API의 CORS 허용 출처를 쉼표로 지정. 기본은 같은 출처 |
| `PUBLIC_NAVER_MAP_CLIENT_ID` | 없음 | 공개 가능한 네이버 지도 클라이언트 ID |

CLI는 `--output`, `--state-dir`, `--page-size`, `--max-calls`, `--max-daily-calls`도 지원한다. 기본 공개 경로는 `public/data`, 상태 저장 경로는 `.cache/evchargingstation`이다.

| CLI 종료값 | 의미 | 파일 처리 |
| --- | --- | --- |
| `0` | 수집·정규화·공개 완료 | 완전한 새 manifest로 교체 |
| `1` | API, 예산, 입력 형식 또는 저장 오류 | 기존 공개 manifest와 데이터를 유지 |
| `2` | 서비스키 미설정 또는 CLI 인자 오류 | 기존 파일 유지. 키가 없고 manifest도 없을 때만 빈 안내 manifest 생성 |

예산 파일은 실제 계정 전체 쿼터를 조회하는 기능이 아니다. 이 수집기 밖에서 같은 서비스키를 사용하는 호출은 계산에 포함하지 못한다. KST 일일 경계도 애플리케이션의 보수적 운영 기준이며 제공기관의 쿼터 초기화 시각을 검증한 결과는 아니다. CI 캐시를 잃으면 호출 누계도 복원할 수 없으므로 반복 전체 수집을 피해야 한다.

## API 계약

| 항목 | `getChargerInfo` | `getChargerStatus` |
| --- | --- | --- |
| 주소 | `https://apis.data.go.kr/B552584/EvCharger/getChargerInfo` | `https://apis.data.go.kr/B552584/EvCharger/getChargerStatus` |
| 역할 | 위치·충전기·운영 정보와 상태의 전체 기반 목록 | 최근 변경된 충전기 상태 |
| 응답 요청 | `dataType=JSON` | `dataType=JSON` |
| 페이지 크기 | 10~9,999 | 10~9,999 |
| 시간 범위 | 없음 | `period` 1~10분, 기본 5분 |
| 본 구현 수집 범위 | 지역 조건 없는 전국 목록 | 지역 조건 없는 전국 변경분, 기본 10분 |

가이드 요청표는 `statId`, `chgerId`를 필수라고 표시하지만 같은 문서의 전체 목록조회 예제에는 두 변수가 없다. 본 구현은 예제에 따라 전국 목록을 조회한다. 공식 포털은 `ServiceKey`, 가이드는 `serviceKey`로 표기하며 본 구현은 가이드의 `serviceKey`를 사용한다. 실제 키 연결 검증 시 확인할 항목이다.

HTTP 성공 여부와 API 결과코드를 모두 확인한다. 문서의 최상위 JSON, `response/header/body` 형식 JSON, XML 응답과 게이트웨이 XML 오류를 처리한다. 빈 변경분은 정상일 수 있지만, 오류·깨진 JSON·잘못된 전체 건수·부족한 페이지를 정상 빈 데이터로 바꾸지 않는다.

상태 코드는 본문 필드표보다 공통코드표가 더 완전하다.

| 코드 | v1.25 공통코드표 |

| `0` | 알수없음 |
| `1` | 통신이상 |
| `2` | 충전대기 |

본문 필드표에서는 `2`를 사용가능이라고 쓰고 `6`, `9`를 생략했다. 알 수 없는 새 코드는 보존하고 사용가능 상태로 추정하지 않는다.

| `01` | DC차데모 |

## 정규화 원칙

- `statId`, `chgerId`, 기관·지역·타입 코드는 문자열로 관리한다. 충전기 ID `02`의 0을 보존한다.
- 충전기 기본 식별자는 `(statId, chgerId)`이다. 전체 목록의 중복 식별자는 병합해서 숨기지 않고 수집 오류로 처리한다. 상태조회에서 동일 식별자의 기관이 바뀌면 전체 목록을 다시 받는다.
- `output`은 kW이다. 유효한 양수인 경우만 `outputKw`로 변환하고 `50+50` 같은 불명확한 값은 수치로 추측하지 않는다.
- 주차료·이용자 제한의 빈값은 `null`이다. 빈값을 무료·제한없음으로 바꾸지 않는다.
- 충전소 내 충전기별 정보가 다르면 제한은 하나라도 Y일 때 제한 있음, 주차료는 하나라도 N일 때 유료로 표시한다. 확인되지 않은 값은 보수적으로 남긴다.
- 좌표가 없거나 0, NaN, 축이 뒤바뀐 값 또는 한국 주변 검증 범위 밖이면 지도에 찍지 않는다. 목록은 유지한다. 범위 검증은 구현상 품질 검사이며 API가 명시한 좌표계 계약을 대신하지 않는다.
- `delYn=Y` 항목은 공개 목록에서 제외한다. 전국 목록이 비었거나 삭제 항목만 남으면 정상 데이터로 교체하지 않는다.
- `useTime`은 자유문장이다. 일괄적으로 현재 영업 중 여부로 변환하지 않는다.
- `trafficYn`은 문서상 편의제공 여부만 정의되어 있다. 장애인 접근성 등으로 의미를 확대하지 않는다.
- `addrDetail`, `location`, `note`, 운영기관 연락처를 보존한다. API가 제공하는 추가 원본 필드도 비공개 수집 상태에는 남지만 공개 계약에 없는 항목을 화면에 자동 추가하지 않는다.

## 최신성의 의미와 복구

`statUpdDt`는 상태변경·통신이상·통신복구 시각이다. 주기적인 장비 통신 확인 시각이 아니다. 값이 오래됐다는 이유만으로 통신장애라고 판단하지 않는다.

| 공개 필드 | 의미 |
| --- | --- |
| `charger.statusChangedAt` | 원본 `statUpdDt`를 해석한 상태 변경 시각 |
| `charger.observedAt` | 해당 충전기 원본 항목을 포함한 API 페이지를 수신한 시각 |
| `statusCoverageAt` | 전체 목록 또는 연속된 변경분 조회가 시작된 시각. 모든 페이지의 검증이 끝난 뒤에만 공개 |
| `inventoryUpdatedAt` | 전체 기반 목록 수집이 완료된 시각 |
| `generatedAt` | 공개 분할 파일을 생성한 시각 |

원본 `yyyyMMddHHmmss`의 시간대는 가이드에 명시되어 있지 않다. 한국 서비스라는 근거로 KST를 적용하여 UTC ISO 문자열로 내보내며 실제 응답 연결 시 검증할 구현 가정이다.

전체 수집의 확인 범위를 완료 시각으로 올리지 않는다. 먼저 받은 페이지의 상태가 나중에 받은 페이지의 수신 시각까지 확인된 것은 아니기 때문이다. 각 충전기는 자신의 `observedAt`도 함께 가진다.

변경분을 모두 읽었고 이전 확인 범위와 현재 조회 창이 이어질 때만 `statusCoverageAt`을 진행한다. 여러 페이지의 조회창은 요청 때마다 이동하므로 수집 시작뿐 아니라 **수집 완료 시각까지** 이전 확인 범위와 겹치는지 검사한다. 예를 들어 이전 확인 9분 뒤에 시작해 2분 걸린 10분 변경분 조회는 전체 복구가 필요하다. 정상 빈 변경분은 기존 충전기를 유지한다. 오래된 변경 이벤트가 나중에 도착해도 새 이벤트를 덮어쓰지 않는다. 조회 공백이 설정된 `period`보다 길거나 기반 상태를 잃으면 전체 목록을 다시 수집한다. 실패한 실행은 공개 파일을 바꾸지 않으며 다음 실행에 전체 복구를 요청한다.

변경 항목의 `stat`가 비어 있거나 `statUpdDt`가 누락·파싱 불가이면 `INVALID_STATUS`로 거부한다. 불완전한 응답으로 이전 충전대기 상태의 확인 시각을 연장하지 않는다. 기존 공개 파일과 확인 시각을 보존하고 다음 실행에서 전체 복구한다. 값이 존재하는 새 상태코드는 보존하여 화면에서 미확인 코드로 구분한다.

상태 API는 고정 snapshot ID나 cursor를 제공하지 않는다. 조회가 진행되는 동안 상대 시간 창과 `totalCount`가 움직일 수 있다. 구현은 각 페이지의 실제 개수를 검증하고 관측한 최대 페이지 범위까지 읽으며, 기본 5분 실행·10분 조회 창의 중첩으로 누락 위험을 줄인다. 제공기관이 특정 한 시점의 완전한 상태 스냅샷을 보장한다고 주장하지 않는다. 전체 정보 조회의 전체 건수가 도중에 바뀌면 불완전한 inventory를 공개하지 않고 실패 처리한다.

GitHub Actions 5분 예약은 정확한 실행 시각을 보장하지 않는다. 지연 시 상태가 오래됐음을 표시하고 다음 실행에서 전체 복구한다. 지도 탐색 화면이 실시간 가용 상태로 집계할 수 있는지 판단할 때는 상태변경 시각이 아니라 수집 확인 시각과 연속 수집 범위를 사용한다.

## 지역 코드와 공개 파일

v1.25 공통코드표에는 `12`가 `전남광주통합특별시`, `51`이 `강원특별자치도`, `52`가 `전북특별자치도`로 기재되어 있다. 이는 **해당 API 코드표의 표기**를 옮긴 것이며 이 문서가 실제 행정구역의 법적 현황을 확정하는 것은 아니다. 상세 코드표에는 이전 코드도 일부 남아 있다.

수집은 시도 코드를 고정해 반복하지 않는다. 전국 목록을 받은 뒤 실제 `zcode`에 따라 분할한다. 새 코드와 이전 코드도 버리지 않고 그대로 목록에 반영한다. 등록되지 않은 코드는 `지역 코드 값`으로 표시한다.

```text
public/data/manifest.json
public/data/releases/<수집ID>/regions/<지역코드>.json
.cache/evchargingstation/state.json
.cache/evchargingstation/budget.json
```

모든 분할 파일을 먼저 저장한 다음 manifest를 원자적으로 교체한다. 실패한 수집이 부분 목록을 기존 정상 목록 대신 게시하지 않는다. 최근 배포본을 보존하지만 오래된 manifest를 계속 보유한 클라이언트에서 분할 경로가 404이면 manifest를 다시 읽고 새 경로로 조회해야 한다.

서버는 `public/`의 파일, 공개 분할 데이터, 공개 설정만 제공한다. 저장소 루트·상위 경로·숨김 파일·공개 경로 밖을 가리키는 심볼릭 링크를 제공하지 않는다.

| HTTP 경로 | 응답 |
| --- | --- |
| `/config.js` | 공개 지도 설정, 같은 출처의 `/api` 주소 |
| `/api/manifest.json` | 현재 데이터 상태와 지역별 분할 경로 |
| `/api/<manifest의 region.path>` | 해당 불변 지역 JSON |
| `/api/regions/<지역코드>.json` | 현재 manifest의 지역 경로로 연결한 JSON 응답 |
| `/api/regions` | 현재 지역 메타데이터 목록 |
| `/api/health` | 모드·설정 여부·확인 시각·공개 가능한 오류 코드 |

HTTP 새로고침은 사용자별 공공 API 요청을 생성하지 않는다. 한 백그라운드 수집기가 전체 사용자를 위한 상태를 갱신한다.

## 이 API에 없는 정보

요금, 대기 차량 수, 실제 주차면 점유, 예약 생성·취소, 차량 SOC, 충전 종료 예정시각, 사용자 후기·사진은 이 API 명세에 없다. 현재 충전 시작 시각으로 경과시간을 계산할 수 있지만 남은 대기시간은 추정하지 않는다. 이러한 값은 별도 공식 데이터 계약과 검증이 이루어지기 전까지 제공 정보로 표시하지 않는다.

## 검증 범위

`tests/test_api.py`는 로컬 테스트 자료로 JSON·XML 파싱, 게이트웨이 오류, 키 인코딩, 모든 페이지 수집, 부분 응답 거부, 호출 예산, 삭제·중복 처리, 오래된 변경 시각, 빈 변경분, 순서가 바뀐 이벤트, 10분 초과 복구, 신규 충전기 복구, 기존 manifest 유지, 서비스키 없는 CLI와 실제 HTTP 요청 경로·CORS·공개 파일 범위를 검사한다.

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

실제 HTTP 테스트는 localhost 소켓을 사용한다. 소켓 사용을 제한하는 실행 환경에서는 허용된 테스트 환경에서 실행해야 한다. 테스트 자료는 `tests/` 내부에만 있으며 정상 수집 데이터나 실시간 충전소로 게시하지 않는다.

실제 서비스키 연결 후 남은 검증은 전체 목록 응답 및 실제 페이지 규모, JSON 형식, 요청변수 표기, 시간대, 실제 일일 호출 예산, 운영기관별 상태 전달 지연, 지역코드 전환 데이터의 분포이다. 이 항목들은 구현 완료와 별도로 확인해야 한다.
