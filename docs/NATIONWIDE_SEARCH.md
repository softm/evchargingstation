# 전국 검색과 상태 확인

2026-10-21 KST.

## 검색 범위

- 검색 범위에 `전국 전체`, `지도 주변`, 개별 지역을 제공한다.
- 지도 주변에서 이름·주소를 입력하면 전국 검색으로 전환한다. 이 자동 전환 후 검색어를 지우면 지도 주변으로 돌아간다.
- 모바일에서 이름·주소를 검색하면 목록을 자동으로 보여 준다. 검색어가 있는 공유 링크도 로드 후 목록을 표시한다.
- 사용자가 직접 전국을 선택했다면 검색어 없이도 전체 수집 충전소를 조회할 수 있다. 60개씩 목록을 추가하고, 지도는 현재 화면 내 마커만 기존 상한으로 그린다.
- 전국 검색에서는 지도 이동·선택 마커로 인한 이동에도 전국 범위를 유지한다. `이 지역 검색` 또는 검색 범위 선택으로 지도 주변으로 전환한다.
- 커넥터·출력·대기 조건은 같은 충전기에 적용한다. 모르는 주차료와 출입 제한, 오래된 상태는 기존과 동일하게 처리한다.

## 데이터 구조

빌드 시 검증된 모든 지역 파일로 `data/search/stations-<내용 해시>.json.gz`를 생성한다. 수집 API를 별도로 다시 호출하지 않는다. manifest의 `searchIndex`에 충전소·충전기 건수와 압축 전후 용량을 게시한다.

검색 자료는 충전소 ID·이름·주소·좌표·운영사·운영시간·주차/출입 구분과, 각 충전기의 ID·커넥터·출력·상태·관측 시각만 포함한다. 지역별 수집 확인 시각도 보존한다. 회원 요금·층수·과거 충전 기록 등은 이 자료에서 추정하지 않는다.

전국 목록의 항목을 선택하면 해당 지역 원본을 읽어 상세를 표시한다. 로딩 중 요약 데이터를 완전한 상세처럼 표시하지 않는다. 선택 변경·닫기·검색 범위 변경 후 도착한 응답은 새 화면을 덮지 않는다. 검색 자료는 한 버전을 캐시하고 동시 요청을 공유하며 실패 후 재시도할 수 있다. 배포 중 이전 검색 파일이 404가 되면 manifest를 다시 읽고 한 번 재조회한다.

`data-status.html`에서 전국 검색 자료 건수·gzip 용량을 표시한다. 배포 검사는 실제 전국 검색 파일의 압축 해제·전체 충전소/충전기 수·중복 ID·지역 참조를 검사한다.

## 상태 최신성: 확인한 문제와 한계

2026-10-21 12:57 KST 운영 자료 점검에서 철원역사문화공원 3기의 마지막 관측은 10:52 KST였다. 원본 상태 코드는 모두 대기였지만 10분을 넘었으므로 현재 대기 3기로 집계할 수 없었다. 표시된 대기 0기는 최근 확인된 대기가 0기라는 뜻이며, 전체 3기는 확인 필요에 포함된다.

원인은 GitHub의 5분 예약 설정과 실제 실행 시각 사이의 큰 공백이었다. 확인한 예약 실행은 08:27과 10:50 KST 등으로 떨어져 있었다. GitHub는 예약 작업의 지연·누락 가능성을 공식적으로 안내한다. 실행 기록이 없는 구간의 현재 상태를 과거 코드로 채우지 않는다.

이번 수정:

- 상세 상태 요약 바로 아래에 가장 최근 수집 확인 시각·경과 시간·수집 지연을 표시한다.
- 게시된 자료 재조회 버튼을 제공한다. 이는 API 원본을 즉시 재수집하는 버튼이 아니다.
- 화면의 1분 주기 게시 자료 확인과 서버의 원본 수집을 구분한다.
- 신선도가 지난 경우 상단 수집 현황 링크도 `상태 갱신 지연`으로 표시한다.
- 코드 배포에서 수집 확인이 5분 이내이고 파일이 존재할 때만 캐시 재사용을 허용한다. 오래된 자료는 `auto` 수집을 시도하며, 갱신 실패 시 기존 정상 결과와 원래 확인 시각을 보존한다.

상시 최신 상태 보장은 아직 해결되지 않았다. 현재 GitHub Pages 정적 배포와 Actions 예약만으로는 조회 시 원본 API 요청 또는 정시 갱신을 보장할 수 없다. 기존 `server.http_server.Runtime`에는 서버 비밀키를 사용하는 5분 백그라운드 수집 기능이 있으나, 운영 서비스용으로 호스팅·연결되어 있지 않다. 지속 실행 서버를 배치하고 공공데이터 키를 서버 비밀 설정으로 전달한 뒤, 공개 API URL을 연결해야 한다. API 키를 브라우저나 공개 저장소에 넣는 방식으로 대신하지 않는다.

공식 참고: [GitHub 예약 실행의 지연·누락 안내](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
